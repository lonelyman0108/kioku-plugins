# AstrBot 插件：Kioku 记忆

让 AstrBot 的机器人用上 Kioku 的长期记忆：

- 调用模型之前：Kioku 里的人格与基础规则追加到系统提示（很少变，不破坏服务商的提示缓存）；这一轮相关的记忆与关于对方的事实作为临时的额外用户内容附上（每轮都变，不进对话历史）。
- 模型回复之后：把这一轮（用户的话与回复）交给 Kioku，攒批之后整理成关于对方的记忆。不等它完成，不拖慢回复。
- Kioku 不可用、超时或拒绝请求时只记日志，不注入，不打断对话。

插件只转发：平台、群与发言人的账号原样上报，由 Kioku 解析成联系人、判断是不是本人、按群切换人格；注入什么、怎么抽取都由 Kioku 决定。

## 绑定别的平台的账号：`/bind`

同一个人在几个平台都和机器人私聊时，Kioku 里是几个联系人。用 `/bind` 把它们绑成同一个人，记下的事实和私聊里的记忆就合在一起，用哪个平台聊都读得到：

1. 在一个平台（例如 QQ）私聊机器人，发 `/bind`，机器人回一个 8 位的绑定码，10 分钟内有效、只能用一次。再发一次 `/bind` 会换一个新码，旧码作废。
2. 在另一个平台（例如 Telegram）私聊同一个机器人，发 `/bind <绑定码>`。机器人先说明要绑到哪个账号（平台、平台上的名字、只露出头尾几位的账号），以及绑定之后两边私聊里记下的内容互相读得到。这一步什么都不改，码也不用掉。
3. 看清是自己的另一个账号之后，再发 `/bind <绑定码> 确认`。这个平台的账号会并进第一步的那个账号（名字留第一步那边的）。码里可以带空格或连字符，大小写不论。没经过第二步就发「确认」的，也只先给第二步的说明。

- 只在私聊里用：群里发 `/bind` 只会提示去私聊；在群里发了带码的 `/bind`，这个码已经公开了，机器人会把它作废，请回私聊重新申请。
- 第一步的账号在 Kioku 管理界面里被成员标记为「这是我」、第二步的账号没标记成同一个成员时，确认之后也不马上合并，机器人回「已提交，等对方在管理界面确认」：要那个成员本人在待处理或联系人页里确认（7 天内），确认之后才合并。这个账号的私聊算那个成员的本人私聊，码泄露了别人就能把自己的账号挂过来，所以要本人确认。两个账号都标记成同一个成员时直接合并。
- 第二步的账号被标记成了别的成员时绑不了；第一步的账号没标记时，可以反过来，在已标记的那个账号上发 `/bind` 获取绑定码。
- 输错的次数有上限：同一个账号一小时 5 次，同一个机器人一小时合计 1000 次，超了要等一会儿再试。只有发来的码对不上任何一个绑定码才算输错：第二步的说明、码已经用过或过期、在群里把码作废都不算。
- 绑定码只在同一个应用（同一个访问密钥所属的应用）里有效。访问密钥要能写联系人的事实，否则机器人会回复不能绑定。
- 绑定码和 `/bind` 这一轮不交给模型，也不会被整理成记忆。

## 要求

- AstrBot 4.24.1 以上：召回作为临时的额外内容附上（不进对话历史）要用到的接口从这个版本才有，`metadata.yaml` 里声明了，版本不够时 AstrBot 拒绝加载
- Python 3.11 以上（插件带着的 Kioku 客户端要求）
- 一个 Kioku 应用：运行时选 **astrbot**（召回块会直接带记忆的正文，群聊机器人不必调工具去读），签发一个访问密钥。访问密钥能写联系人与会话摘要时，对话才会被整理成记忆
- 访问密钥只给群聊用得到的归属：读通用、人格、应用、联系人与会话，写联系人与会话，最高敏感级公开，也就是签发时的「群聊机器人」预设（应用设置里开了「本人私聊时读取本人记忆」时，再加读本人、最高敏感级内部）。带着会话上下文的请求会按群聊、私聊再收紧，但访问密钥本身的权限越小，泄露时的损失越小

不要再给这个机器人接 Kioku 的 MCP 工具：MCP 请求不带会话上下文，按访问密钥的全部权限读写，群里的人能借它读到群里本来读不到的记忆。

## 安装

插件目录里带着由 Kioku 的接口生成的 Python 客户端 `kioku_client`，整个目录复制过去即可：

```sh
cp -R plugins/astrbot_plugin_kioku <AstrBot 的数据目录>/plugins/
```

然后在 AstrBot 管理面板里重载插件，填写配置：

| 配置 | 说明 |
|---|---|
| `kioku_url` | Kioku 的地址，例如 `http://127.0.0.1:18920`，不带 `/v1` |
| `kioku_key` | 上面签发的访问密钥 |
| `boot` | 是否注入启动加载（Kioku 里的人格与基础规则）；人格完全用 AstrBot 自己的设置时关掉 |
| `timeout` | 请求 Kioku 的超时（秒），默认 4 |

## 同步客户端

`kioku_client` 由 Kioku 的接口生成，来源提交记在 `kioku_client/SOURCE`。Kioku 改了应用调用的接口、重新生成 `sdks/python` 之后，在本仓库根目录运行：

```sh
scripts/sync-client.sh <Kioku 仓库的路径>
```

## 开发

```sh
cd plugins/astrbot_plugin_kioku
uv run pytest
uv run ruff check . && uv run ruff format --check .
```

测试不装 AstrBot：`tests/stubs/astrbot` 是只有插件用到的那几个名字的替身，按 AstrBot 4.x 的文档写。
