# 清理冲突记忆工具 计划（kioku-plugins）

> 状态：进行中　　开始：2026-11-17　　负责人：agent 实现，维护者审阅合并
> 全部完成后，文件头改为「已完成 YYYY-MM-DD」，用 `git mv` 移到 `docs/archive/plans/`。

在 `kioku` 命令里新增第三方冲突记忆工具（Lore 及常见记忆 MCP）的检测与卸载能力：支持独立子命令 `kioku clean`，并接进交互向导（`panel.mjs` / `wizard.mjs`）、`kioku setup`、`kioku install` 与 `kioku doctor`，避免同一平台上多套长期记忆同时注入和写入。

## 决策摘要

| # | 决策 | 采纳 | 可推翻条件 |
|---|---|---|---|
| 1 | 冲突处理默认策略 | 交互模式下（向导、TTY `setup`）提示并询问是否先卸载；非交互模式下（无 TTY 的 `setup` / `install`）默认阻塞并报错提示传 `--remove-conflicts`，防止无声改动他人配置或造成双写 | 实际使用中若反馈阻塞过多，可调整为仅部分高风险冲突阻塞 |
| 2 | 命令形态 | 新增独立子命令 `kioku clean [平台]`，同时集成到向导、`setup`、`install`、`doctor` | — |
| 3 | 覆盖范围 | 完整覆盖 Lore（各平台插件、MCP、钩子、环境变量、兼容补丁）及常见记忆 MCP（`mem0`/`openmemory`、`supermemory`、`@modelcontextprotocol/server-memory`、`cipher`、`claude-mem` 等高置信度规则）；仅命中 `memory` 键名但特征不明的只告警不自动删 | 误报率高时收紧特征匹配，或将通用 MCP 降级为仅告警 |
| 4 | 清理边界 | 只解除当前目标平台上的接入配置，绝不跨平台清理，也不删 `~/.lore/docker`、`~/.lore/config.json` 等数据；非托管目录（非 symlink、缺标记）跳过并告警；含密钥的配置文件修改时不留 `.kioku-backup` | — |
| 5 | 指令文件处理 | 精确移除 Lore 托管的 `~/.claude/lore-guidance.md` 及 `~/.claude/CLAUDE.md` 中的 `@~/.claude/lore-guidance.md` / `@import ~/.claude/lore-guidance.md` 导入行；手写说明、`AGENTS.md` 等只提示不自动改 | — |
| 6 | 卸载实现方式 | 不依赖调用 `npx @loremem/cli uninstall`，把各平台确定性清理逻辑（优先调宿主命令如 `claude`/`codex`/`openclaw`，兜底改文件）内置到 `packages/core/lib/`，零外部依赖 | — |

## 各平台冲突特征与清理清单

### Lore

参考 Lore 各平台安装/卸载实现：

- **Antigravity (`agy`)**：`~/.gemini/config/mcp_config.json` 中 `mcpServers.lore`（或 URL 含 `/api/mcp` 且键/特征为 Lore）；`~/.gemini/config/plugins/lore` 与项目 `.agents/plugins/lore`（仅限含 Lore 插件清单或指向 Lore 的软链）。
- **Gemini CLI (`gemini`)**：`~/.gemini/settings.json` 中 `mcpServers.lore`；`~/.gemini/extensions/lore`（若存在扩展链接/目录，提示或调 `gemini extensions uninstall` / 移除托管软链）。
- **Claude Code (`claude-code`)**：若存在 `claude` 命令调 `claude plugins uninstall lore@lore`、`claude mcp remove lore`；清理 `~/.claude/settings.json` 的 `env` 中 `LORE_BASE_URL`、`LORE_API_TOKEN`、`LORE_HOME`、`LORE_CLIENT_TYPE`、`LORE_SKILLS_ENABLED`；移除 `~/.claude/lore-guidance.md`、`~/.claude/CLAUDE.md` 中精确导入行、`~/.claude/plugins/cache/lore`。
- **Codex (`codex`)**：若存在 `codex` 命令调 `codex plugin marketplace remove lore`、`codex mcp remove lore`、`codex mcp remove lore-skills`；移除 `$CODEX_HOME/plugins/lore-local-marketplace`、`plugins/cache/lore`、`hooks/lore`；清理 `$CODEX_HOME/hooks.json` 中命令含 `/hooks/lore/hooks/recall-inject` 的条目；按行移除 `$CODEX_HOME/config.toml` 的 `[plugins."lore@lore"]`、`[mcp_servers.lore]`、`[mcp_servers.lore-skills]` 段。
- **OpenCode (`opencode`)**：`~/.config/opencode/plugins/lore-memory.js`（校验含 `@lore-managed-opencode-plugin` 标记才删，否则保留并警告）；`opencode.json` 中的 `mcp.lore` 与 `plugin` 里的 Lore 条目；若存在 `~/.lore/opencode-compat.json` 且可恢复则调用/提示恢复兼容设置。
- **OpenClaw (`openclaw`)**：若存在 `openclaw` 命令调 `openclaw plugins disable lore`、`openclaw plugins uninstall lore`；移除 `~/.openclaw/openclaw.json` 中 `plugins.entries.lore`（若 `plugins.slots.memory === 'lore'` 则设回 `memory-core` 或清除）；移除 `~/.openclaw/extensions/lore`。
- **pi (`pi`)**：`~/.pi/agent/extensions/lore`（仅删除符号链接；普通目录保留并警告）。
- **DeepSeek Harness (`dsh`)**：清理 `$DSH_HOME/cordis.patch.yml` 中由 Lore 管理的块/行（`lore` 插件与 `lore-mcp.mjs` 桥接）。
- **Hermes (`hermes`)**：`~/.hermes/skills/lore_memory` 或 `~/.hermes/plugins/lore_memory`（仅删符号链接或含 Lore 标记的目录）；`.hermes/.env` 中 `LORE_*` 清理；若当前 `memory.provider` 为 `lore_memory`，通过 `hermes config set memory.provider ""` 清除或提示。

### 常见记忆 MCP（高置信度匹配）

扫描各支持 MCP 的配置文件（`agy` 的 `mcp_config.json`、`gemini` 的 `settings.json`、`codex` 的 `config.toml`、`opencode` 的 `opencode.json`、`claude-code` 的 `~/.claude.json` / `settings.json` 或宿主命令）：

- **Mem0 / OpenMemory**：键名 `mem0` / `openmemory`（且命令/参数/URL 未指向无关服务），或 `command`/`args`/`url` 含 `mem0-mcp`、`@mem0/`、`openmemory`。
- **Supermemory**：键名 `supermemory`，或 `url`/`args` 含 `supermemory.ai`、`@supermemory/`。
- **MCP 官方 Memory Server**：`args`/`command` 含 `@modelcontextprotocol/server-memory` 或 `mcp-server-memory`（单靠键名 `memory` 但特征不明的，只报告警告不自动删）。
- **Cipher**：`args`/`command` 含 `@byterover/cipher`（或键名 `cipher` 且命令匹配）。
- **Claude-Mem**：Claude Code 中插件 `claude-mem` 或对应 MCP 条目特征。
